# 毎朝の段取り（自動化の手順）

このファイルは、クラウドの定期実行が毎朝読む手順です。人が読むための説明は同じフォルダの `README.md` にあります。

## やること

今日のToDoを読んで、日誌に「今日の段取り」の節を1つ足す。それだけです。

### 1. 今日の日付を確かめる

`TZ=Asia/Tokyo date +%F`（例 `2026-10-21`）。コンテナの時計はUTCなので、JSTで取らないと日付が1日ずれます。

### 2. 今日のToDoを読む

アドネス株式会社の組織IDを**必ず明示**して読む。

- 組織ID: `79e5df38-ffbb-4a95-9d41-f5968427c653`
- `execute` の `organization_id` に渡す（`switch_organization` は使わない。APIキーの既定組織を変えてしまい、高山さんの他の会話の向き先まで変わるため）
- 読むもの: `list_todays_goals` → 出てきたゴールを `get_goal` で1件ずつ（理想と本文）

### 3. 段取りを書く

`days/YYYY-MM-DD.md` に `## 今日の段取り` の節を足す（ファイルが無ければ `# YYYY-MM-DD（曜）` の見出しから作る。すでに「今日の段取り」の節があれば、二重に書かずそのままにする）。

ゴール1件につき1行、**最初の一手まで**書く。形は:

```
- **ゴールの題** — いまの状態。→ 最初の一手（具体の動作）。`ゴールID`
```

書き方の決まり:

- 「最初の一手」は、読んだ人がそのまま始められる具体の動作にする（「確認する」ではなく「CRMリスト45b4b8c8でstaleを出す」のように）
- 期限が今日・明日のものを先に並べる
- 人の返事待ち・判断待ちで止まっているものは、**誰のボールかを書く**
- 本文から読み取れないことは推測で書かず、「本文に無し」と書く

### 4. commit して push する

`master` へ push する（日誌の正本は master。高山さんがスマホから読む枝）。

```
git add days/ && git commit -m "日誌：今日の段取り（自動）" && git push origin master
```

push が失敗したら、4回まで待ち時間を倍にして再試行する（2秒・4秒・8秒・16秒）。それでも失敗したら、何が起きたかを応答に書いて終わる。

## やらないこと（無人で動くので、ここは固く守る）

- ゴールを**変えない**（本文の書き込み・完了・理想の変更・子ゴールの作成をしない）
- **コメントを書かない**（進捗報告のコメントは投稿しない決まり。進捗はゴールの状態が表す）
- 組織の**外へ送らない**（メール・LINE・Lステップ・外部API）
- `days/` 以外のファイルを変えない
- 読めなかった・分からなかったことを**埋めない**。分からなければ「分からなかった」と書く

## 判断に迷ったら

書かずに止まる。無人の実行で迷ったまま書くと、高山さんが朝いちばんに読む段取りが間違いになる。
止まった時は、何が分からなかったかを `days/YYYY-MM-DD.md` の段取りの節の末尾に1行書く。
